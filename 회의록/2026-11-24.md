# 11/24 회의: 최종 아이디어 선정

- **날짜:** 2026-11-24
- **참석:** 유진, 예림, 주은
- **안건:** 후보 아이디어 비교 및 최종 선정

## 결정 사항

> ✅ **최종 아이디어: 「나만의 감사실」**
> 공개 감사사례를 근거로 내 업무의 위험요인을 미리 점검해 주는 AI

## 논의 과정

### 1. 후보 압축

세 명 모두 아래 두 아이디어가 좋다는 의견을 냈어요.

| 후보 | 한 줄 요약 |
|---|---|
| **나만의 감사실** (예림) | 공개 감사사례를 검색·분석해 현재 업무와 비교하고 위험요인을 진단하는 서비스 |
| **전임자봇** (유진) | AI가 전임자를 인터뷰해 답변을 업무 지식으로 쌓고, 후임자의 질문에 답하는 서비스 |

※ 두 아이디어 모두 [11/22 아이디어 발굴 회의](2026-11-22.md)에서 나왔어요.

### 2. 선정 기준

팀원 **전원이 개발 경험이 없는 비개발자**라는 점을 감안해, **구현하기 쉬운 아이디어**를 고르기로 했어요.

### 3. AI 비교 분석 (요약)

생성형 AI에게 두 아이디어의 구현 구조와 난이도를 비교 분석하게 했어요.

**난이도 평가** (5점에 가까울수록 어려움, 간이 MVP 기준의 주관적 평가)

| 평가 항목 | 전임자봇 | 나만의 감사실 |
|---|---|---|
| 데이터 확보 | 2 | 4 |
| AI 기능 구현 | 4 | 3 |
| DB 구축 | 2 | 3 |
| UI/UX 개발 | 2 | 2 |
| 결과물 완성도 확보 | 3 | 3 |
| **종합 난이도** | **중상 (3.5)** | **중 (3.0)** |

**어려운 지점이 서로 달라요**
- **전임자봇:** AI 구현이 어려워요. 좋은 인터뷰 질문 설계, 답변에 따른 후속 질문, 답변의 구조화, 전임자가 하지 않은 말을 AI가 지어내지 않게 막는 것이 핵심 과제예요.
- **나만의 감사실:** 데이터 구축이 어려워요. 감사보고서마다 형식이 달라 정리가 필요하고, 업무 분야별 분류, 실제 위험이 비슷한 사례를 찾는 검색, 법적 정확성 확인이 과제예요.

**평가 기준별 비교**

| 평가 기준 | 우세한 아이디어 |
|---|---|
| 생성형 AI 활용의 차별성 | 전임자봇 |
| 발표 시연의 직관성 | 전임자봇 |
| 실무 활용성 | 나만의 감사실 |
| 공공기관 적용 가능성 | 나만의 감사실 |
| 향후 서비스 확장성 | 둘 다 높음 |

### 4. 함께 검토한 반대 의견

다른 AI 대화에서는 **전임자봇이 더 쉽다**는 의견도 나왔어요.
- 전임자봇은 사용자가 대화로 데이터를 만들어 주므로 데이터를 모을 필요가 없다.
- 감사실은 감사보고서 수집, PDF·한글 파일 텍스트 추출, 분류 같은 데이터 작업이 프로젝트의 대부분을 차지할 수 있다.
- 대신 '실제 공개 데이터로 시연'하는 맛은 감사실이 더 좋다.
- 절충안으로 "전임자봇을 메인으로, 감사사례는 인터뷰 질문에 활용" 하는 방안이 제안됐다.

또한 위 분석의 난이도 표(감사실이 더 쉬움)와 기준별 비교의 "구현 편의성: 전임자봇" 결론이 서로 맞지 않는 부분이 있었어요. AI 분석을 그대로 따르지 않고 팀이 직접 판단했어요.

→ 팀은 종합 난이도 점수와 공공기관 실무 활용성을 근거로 **나만의 감사실**을 선택했어요.

## 선정 후 꼭 지킬 것 (AI 분석에서 나온 주의점)

1. **데이터는 손으로, 작게 시작해요.** 모든 감사보고서를 자동으로 모으지 않고, 공개 감사사례 **20~30건**을 직접 골라 정리해요. 검증된 사례를 쓰는 편이 시연 신뢰도도 높아요.
2. **"검색 → 출처 제시 → 위험 진단" 구조가 반드시 있어야 해요.** 업무를 입력하면 체크리스트만 만들어 주는 수준이면 일반 AI 챗봇과 다를 게 없어요.
3. **AI의 해석과 실제 규정을 구분해서 보여줘요.** 과거 사례를 현재 업무에 그대로 적용하면 안 되므로 관련 규정과 시점을 함께 표시해요.

## MVP 범위 (안)

| 우선순위 | 기능 | 범위 |
|---|---|---|
| 1 | 감사사례 데이터 구축 | 공개 감사사례 20~30건 확보 |
| 2 | 사례 분류 | 계약·회계·인사 등 업무 분야별 분류 |
| 3 | 업무 입력 | 사용자가 현재 업무를 입력 |
| 4 | 유사사례 검색 | 입력 업무와 관련된 사례 3~5건 검색 |
| 5 | 위험 진단 | 위험요인 + 자체 점검 체크리스트 생성 (출처 포함) |

**초기에는 하지 않을 것:** 감사보고서 자동 수집, 실시간 법령 개정 반영, 기관별 내부 규정 연동, 위험도 예측 모델

**추천 기술:** Streamlit(화면) + Python + PyMuPDF(PDF 글자 추출) + LLM API 또는 Ollama + ChromaDB(유사 사례 검색) + SQLite
